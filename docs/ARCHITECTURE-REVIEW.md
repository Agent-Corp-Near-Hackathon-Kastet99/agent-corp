## Growth storage and contributor pricing follow-up

The growth runtime exclusively locks both its data directory and action file for its lifetime. A second runtime sharing either path fails closed. Shutdown rejects new requests, waits for accepted work to settle and then releases locks. Startup failure releases acquired locks. After a crash or forced termination, confirm the old process and effect have stopped before manually removing `.runtime.lock` and the action file's `.lock` file. Interrupted actions remain subject to external verification on restart.

Workers meter against contributor-controlled local prices, seeded by built-in rates. Unknown models and server price mismatches are refused before reservation. Optional `$AGENT_CORP_HOME/prices.json` configures local rates; the server must use matching rates for consistent list-price credit. See the provider integration guide for format.

Review target: inherited MVP plus Step 0 / Agent A completion. Read `CONTEXT.md` and ADR 0001 before exploration. One read-only Explore agent reviewed surviving code, then reviewed fixes again. No ADR conflict. User selected all findings up front; coordinator implemented them sequentially.

A Module's Interface is its test surface. Depth supplies Leverage to callers and Locality to maintainers. Real NEAR and stateful test Adapters meet the Ledger Seam; real child process and test runners meet the worker-session Seam. Existing contract Module earns its Depth, so splitting it into shallow forwarding Modules would add friction.

1. **Accounting-agent Module — fixed.** Files: `server/src/agents.ts`, `ledger.ts`, `near.ts`, `scripts/demo.ts`, `test/agents.test.ts`, `test/ledger-fixture.ts`. Global signing calls previously leaked nonce/order knowledge into policy callers; CEO ignored Board cap; timestamp dedupe skipped legitimate next-period costs; demo had no Board budget. Canonical records now live at Ledger Interface; NEAR Adapter owns signing order; CompanyAgents Implementation owns serialized policy, effective cap, standing-cost dedupe by ledger period/status and close ordering. Demo explicitly proposes, votes and finalizes a machine-readable budget. Leverage: callers request accounting actions without managing signing details. Locality: policy changes and behavioral tests stay together. Deletion test: removing this Module would scatter approval and accounting order across HTTP, timer and demo callers.

2. **Owner-constraints / money Module — fixed.** Files: `server/src/config.ts`, `shared/src/money.js`, `server/web/chain.js`, money/config tests. Amount parsing silently truncated malformed decimals; zero-decimal formatting broke; configuration admitted invalid durations/vendors and rejected legal percentages due binary floating-point. Validated configuration Interface now checks complete inputs; exact money Implementation is shared by server/browser. Leverage: setup and agents receive valid constraints; Locality: precision rules have one home. Tests reject malformed/U128-overflow values, check supported formatting and legal two-decimal percentages. Deletion test: validation and formatting would otherwise reappear across callers.

3. **Signing credentials Module — fixed.** Files: `server/src/credentials.ts`, `near.ts`, `scripts/setup.ts`, credential/config tests. Agent signing silently fell back to full access; generated contract key was discarded and partial setup could lose new secrets. Credentials Interface now atomically stores private files, validates complete deployments, journals each generated credential before remote mutation and retains contract signing key. Runtime policy receives Ledger capability without full setup KeyFile. Missing scoped CEO/oracle key fails closed. Leverage: agents cannot accidentally escalate; Locality: credential persistence/recovery has one home. Setup journals are recovery records, not automatic deployment resume; retained after failure, never logged or committed. Deletion test: callers would each need private-file and privilege rules. Follow-up: initial kill switch now enters `new` atomically through `initially_paused`; setup verifies it before reporting success.

4. **HTTP application Module — fixed.** Files: `server/src/app.ts`, executable `index.ts`, `test/app.test.ts`. Wrong HOUSE_01 import prevented boot; import eagerly loaded local credentials and state; malformed URLs escaped request error handling; default network listener exposed demo signing. Application Interface now takes explicit Store/Ledger Adapters; executable owns lifecycle and loopback listener. Demo actions require `DEMO_ACTIONS=on`, same origin when supplied and demo-mode contract. Static paths resolve real files and reject symlink escape. Timer and HTTP share serialized accounting-agent instance. Leverage: HTTP tests exercise actual routes without keys; Locality: bootstrap and request rules are owned in one place. Deletion test: removing the Module would force callers/tests to construct global state and coordinate lifecycle themselves. Initial no-op worker attachment and pass-through Intents placeholder were removed. Concurrent Agent B handoff later supplied real worker transport and dry mainnet quote Implementations; these are now retained and reviewed through canonical Interfaces. UI/game functionality is preserved.

5. **Worker authentication Module — fixed.** Files: `shared/src/auth.ts`, `server/src/auth.ts`, `worker/src/cli.ts`, auth tests. Worker signed raw nonce while server verified different JSON; mocked verification hid mismatch. Both now use one canonical Interface implementing [NEP-413](https://github.com/near/NEPs/blob/master/neps/nep-0413.md): tagged Borsh payload and SHA-256 digest. Account validation also rejects credential-path traversal; challenge state is bounded/pruned. Leverage: signing/verifying Adapters agree by construction; Locality: payload changes occur once. Actual Ed25519 round-trip and account tampering tests cross signer/verifier Interface. Deletion test: protocol knowledge would duplicate and drift again.

6. **Worker-session Module — fixed.** Files: `worker/src/session.ts`, `cli.ts`, `cap.ts`, `runner.ts`, lifecycle tests. Async offers could start overlapping tasks; disconnect released lock while child ran; cancel was ignored; failed/incomplete/over-cap work lost usage. Session Interface now owns synchronous task claim, durable reservation, meter checkpoint, cancellation, process completion and settlement. Exact final cost commits precisely; nonfinal/interrupted work conservatively charges durable reservation or larger observed usage. Cap publishes replacement memory only after atomic disk success; crash-pending reservation is charged on recovery. Child Implementation drains stderr, preserves UTF-8, separates parse noise from callback failure, handles nonzero exit, timeout and cancellation with forced termination fallback. Leverage: caller sends task/cancel/disconnect; Locality: one lifecycle owns quota and process ordering. Tests cover concurrent offers, cancellation before usage, disconnect, failed persistence/retry, crash recovery, over-cap observations, failed child exit and authoritative final-cost replacement. Deletion test: deleting session would spread these ordering rules back into transport callbacks. Task spanning midnight is charged to its reservation/start day; new task uses current UTC day. Crash lock recovery is deliberately manual after confirming prior process stopped. Concurrent Agent B handoff adds a macOS filesystem sandbox and per-wallet cap; retained with cancellation lifecycle. Shell restriction test passes; signed-in Claude inference remains unverified, and tools stay disabled.

7. **Off-chain Store Module — fixed.** Files: `server/src/store.ts`, `test/store.test.ts`. Mutable references bypassed persistence; disk failure left visible in-memory changes; loaded state was unchecked. Store Interface now returns independent snapshots and validates records; its Implementation writes replacement state atomically before publishing it. Best scores retain only improving records. Leverage: callers request updates without coordinating persistence; Locality: state invariants and recovery tests remain concentrated. Tests cover reload, mutation isolation, corrupt state and failed persistence. Deletion test: durable-update invariants would spread into each HTTP/policy caller.

Three additional runtime defects fixed:

- **Accounting timer Module:** synchronous configuration reload could throw before the Promise rejection handler, crashing executable. Reload now runs inside the handled Promise chain; bootstrap test proves bad configuration is contained and the next interval recovers.
- **Contribution retry Module:** zero-unit reports consumed retry slots indefinitely; persistently failing earlier reports could also starve later valid reports. Exclude zero units and rotate bounded batches. Behavioral test places zero-cost and permanently rejected reports ahead of a valid credit and confirms progress.
- **Worker report Module:** retiring active task before durable completion lost known exact usage after a transient write failure. Retain full report until persistence succeeds; disconnect recovery preserves terminal status, units and reference and retries credit. Real socket test injects a failed completion write and verifies retained output and exactly one credit. Refusal state follows the same persistence order.

Worker report fields now require their actual protocol types before transition, and login RPC has a bounded timeout. Malformed reports cannot remove active work before validation. Final verification and latest counts recorded in FINAL.md.
